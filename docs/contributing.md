# Contributing to the Documentation

Documentation source files live in `docs/` and are written in Markdown. The
root-level `mkdocs.yml` controls site settings, extensions, styling, and
navigation.

## Local development

=== "Documentation only"

    This workflow does not install any Next.js packages.

    ```bash
    npm run setup:docs
    npm run docs
    ```

    Open <http://127.0.0.1:8001/>.

=== "Combined local site"

    ```bash
    npm run setup
    npm run dev
    ```

    Open <http://localhost:3000/docs/>.

MkDocs watches `docs/` and `mkdocs.yml`. Saving a source file rebuilds the
affected pages and signals the browser to refresh.

Use the repository commands rather than a globally installed `mkdocs` binary.
`npm run docs` verifies the pinned MkDocs, Material, and i18n packages and runs
`npm run setup:docs` automatically when they are missing or out of date.

## Translate a page

English is the default source language. French, German, and Arabic translations
use the suffix convention in the same folder:

See the complete [documentation localization guide](reference/localization.md)
for translation coverage, generated routes, fallback behavior, and review
rules.

```text
index.md       # English source
index.fr.md    # French
index.de.md    # German
index.ar.md    # Arabic
```

If a localized file is absent, that language route falls back to the English
page. The language selector and translated navigation are configured in the
`i18n` section of `mkdocs.yml`.

When translating technical documentation:

- Do not translate commands, filenames, ROS package names, topics, services,
  actions, message fields, API paths, configuration keys, or code.
- Preserve Markdown structure, admonitions, tables, IDs, links, image paths,
  and fenced-code languages.
- Update every translation when the English source changes materially, or
  remove a stale localized file so the current English page is used.
- Keep Arabic prose right-to-left; code and terminal blocks remain
  left-to-right through the shared stylesheet.
- Run `npm run check:docs` to build all four languages in strict mode.

Localized documentation routes are `/docs/`, `/docs/fr/`, `/docs/de/`, and
`/docs/ar/` in combined mode.

## Add a page

1. Create a Markdown file in the appropriate folder under `docs/`.
2. Add its path and display title to `nav` in `mkdocs.yml`.
3. Run `npm run check:docs`.
4. Review the rendered page, including narrow-screen table behavior.

Example navigation entry:

```yaml
nav:
  - System Architecture:
      - Overview: system_architecture/architecture.md
      - Interface Table: system_architecture/interfaces.md
```

## Technical writing conventions

| Content | Required form |
|---|---|
| Commands | Fenced block annotated with `bash` |
| Configuration | Fenced block annotated with the data language, such as `yaml`, `json`, or `xml` |
| Identifiers and paths | Inline code, for example `module_manager` or `robotics/` |
| Structured comparisons | Markdown tables with concise column headings |
| Risks and blockers | Admonitions such as `warning` or `danger` |
| Undecided values | `TBD`; never infer or invent a value |
| Engineering values | Reference the controlled JSON or CSV source |

Use language-specific code fences so syntax highlighting and code-copy buttons
work correctly:

````markdown
```yaml
controller_manager:
  ros__parameters:
    update_rate: 100
```
````

For wide tables, keep each cell focused on one fact. The site stylesheet makes
technical tables horizontally scrollable on narrow screens rather than
collapsing their columns.

## Add images within a section

Store documentation images under `docs/assets/images/` with descriptive,
lowercase, hyphen-separated filenames. For raw HTML figures, use the mounted
documentation path so images work from pages at every navigation depth:

```html
<figure class="technical-figure">
  <img
    src="/docs/assets/images/amr-x-base-render.png"
    alt="Early AMR-X mobile base render"
    loading="lazy"
  >
  <figcaption>Early project visualization; not a released design.</figcaption>
</figure>
```

Always provide meaningful alternative text and a caption describing whether
the image is a current capture, concept, or external reference. Third-party
reference imagery must not be presented as AMR-X work. Confirm ownership,
licensing, attribution, and publication permission before external use.

## Links and source control

- Use relative links for pages and assets within `docs/`.
- Add every user-facing page to `nav` in `mkdocs.yml`.
- Commit Markdown source and intentional documentation assets only.
- Do not commit `site/`; it is generated by MkDocs.
- Do not commit `.venv/`, caches, or website build output.

Validate before opening a pull request:

```bash
npm run check:docs  # Documentation only
npm run check       # Documentation and website
```

Both commands run MkDocs with `--strict`, so configuration, navigation, and
documentation warnings fail validation.
